{{- if .Values.secrets.create }}

Three generated secrets must survive every upgrade, and this chart reads its own
Secret back to keep them: NUXT_SESSION_SECRET (rotating it signs everyone out),
IP_HASH_SECRET (rotating it breaks IP-hash continuity against rows already
written) and ADMIN_API_KEY. Take a copy before you ever delete the release:

  kubectl -n {{ .Release.Namespace }} get secret {{ include "trackarr.secretName" . }} -o yaml > trackarr-secrets.backup.yaml

Read the admin API key:

  kubectl -n {{ .Release.Namespace }} get secret {{ include "trackarr.secretName" . }} \
    -o jsonpath='{.data.ADMIN_API_KEY}' | base64 -d; echo
{{- end }}

{{- if .Values.ingress.enabled }}

CHECK THIS BEFORE OPENING THE SITE. api.trustProxy and tracker.trustProxy are
on, so both believe X-Forwarded-For. Your ingress controller must SET that
header from the real peer address and must not pass through one the client
sent, or a member can announce as any IP they like — which defeats the
IP-based anti-cheat and the ban list.

On ingress-nginx, leave `use-forwarded-headers` off in the controller ConfigMap
(the default). Also strip CF-Connecting-IP and True-Client-IP, which the
reference Caddy configuration removes and which nothing removes for you here:
see the commented `configuration-snippet` annotation in values.yaml.
{{- else }}
